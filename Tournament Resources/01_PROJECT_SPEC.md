# 01 Project Spec

## Goal
Run SAMP Cup, a single-day community pickleball tournament (planned: 40 teams, supported 34-42, 9 courts, Final over by 6:37 PM, building vacated by 7:00 PM). Format: 4 random groups with at least 8 group games per team, then the top 4 of each group play a Round of 16, quarterfinals, semifinals and a best-of-3 Final, around the leads' day plan with Sabha 3:30-4:30 PM (see `02_TOURNAMENT_RULES.md`). The app handles schedules, live scores, rankings, brackets, judging, announcements and admin control.

## Users and roles
- Admin (youth coordinator + trusted volunteers): full control.
- Judge (volunteer scorekeeper): sees only assigned court/matches; enters scores and timer events.
- Public (players, parents, spectators): read-only live schedule, scores, group standings, the knockout bracket, each team's lunch time. No login. Mobile-first; also usable on a projector/TV and via QR code.

## Registration
Registration is done offline by a local admin and stored in a Google Sheet. The app does NOT handle signup. It imports teams from the Sheet (read-only) via a Google service account and `gspread`. Sheet is the system of record for registration; the app owns everything from the tournament day onward.

## In scope
1. Google Sheets team import (idempotent, no duplicates on re-sync).
2. Random team-number draw at check-in (team numbers set the groups and group pairings).
3. Group-play schedule (8 games per team, rolling lunch) and knockout schedule per `02_TOURNAMENT_RULES.md`, generated by `sampcup_scheduler.py`.
4. Judge scoring screen with game timer, clock-end and sudden-death handling.
5. Automatic group standings and tie-break explanation.
6. Round of 16 filled from the top 4 of each group; winners advance automatically to the best-of-3 Final (game 3 only at 1-1).
7. Live public pages (schedule, my team, group standings, knockout bracket) via Server-Sent Events.
8. Announcements: in-app banner, email; targeted alerts to affected teams. SMS optional (see open items).
9. Admin dashboard: sync, schedule, court overrides, score corrections, delay shifting, check-in, judge assignment, announcements.
10. Audit log of every score change.

## Out of scope (for now)
Online registration/payment, player accounts, chat, multi-day events, fewer than 35 or more than 45 teams without re-checking (see rules doc).

## Tech stack (recommended)
- Backend: Python 3.12, FastAPI, SQLAlchemy + Alembic, PostgreSQL.
- Frontend: React (Vite) or HTMX/Jinja. Mobile-first, large tap targets for judges.
- Live updates: SSE (server to browser only).
- Sheets: gspread + Google service account.
- Notifications: Amazon SES (email). SMS only after sender registration (see open items).
- Infra: Docker, Terraform, AWS (ECS Fargate + RDS, or a single small EC2/Lightsail for a one-day event if cost matters), GitHub Actions CI/CD.
- Auth: admin and judge accounts with JWT sessions; judges also get a per-court PIN login for speed; public has no auth.

## Quality bar
- Works on phones with poor Wi-Fi: judge screen must queue a score and retry if offline.
- No data loss: DB backups; score changes are append-only audit entries.
- Everything testable with seeded dummy data and a "dry run" mode (simulate a full day in minutes).
